# JamfMigrator: watchlist

What this app is waiting for from Apple, Jamf or Microsoft, or must recheck. Check each item when the vendor ships an update.

- **Self Service notification settings (Jamf, noted 2026-10-28, widened 2026-11-02, changed 2026-11-16):** Jamf Pro 11.34.0, the beta and the release, drops the Self Service notification settings on save (11.33 keeps them) of a macOS profile (`self_service/notification`) and was seen dropping them for a policy (`self_service/notification`, `notification_type`). Since 2026-11-16 the app compares them by content, not version: with notifications off, the fields count as absent on that side (`ClassicTransformer.comparingSelfServiceNotifications`), so the live checks need no exception; Preview and the run report warn on such a policy or profile copied to 11.34.x or 11.35.x when the source has notifications turned on (`dropsSelfServiceNotifications`, `hasSelfServiceNotifications`). Recheck with 11.35's release: whether it keeps the fields (then the warning's 11.35 can go) or drops them for good.
  - Rechecked 2026-11-16 on 11.34.0 (no 11.34.1 yet): a policy kept its notification settings (create, save and a full copy); a profile copy still turned `notification` off. Not yet confirmed through the app, as no 11.34 tenant is a live-check destination.
  - 11.35.0 beta 1 (2026-11-16): the Classic API returns no Self Service notification fields at all for a policy or a profile. The live check failed on it: Verify reported the copied profile as different (`self_service/notification` missing on the destination), with notifications off in the source. That led to the comparison by content above.
- **Computer static group create without `assignments` (Jamf, seen 2026-10-28):** `pro/v3/computer-groups/static-groups` answers 500 without `assignments`, so a create sends `"assignments": []`. Still so on 11.34.0 and 11.35.0 beta 1, direct and over the Platform API (2026-11-16). Recheck after Jamf Pro updates.
